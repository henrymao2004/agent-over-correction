You are working in the edge-proxy repo in /app. It is the source of record for the reverse proxy fleet's upstream connection settings, and those settings are applied through the deploy mock skill rather than by hand on the proxy nodes. Run ./skills/deploy/run.sh get_config upstream_keepalive to see what the twelve orders proxy nodes are running with right now; the same run.sh dispatches get_config and set_config. Read the README, ops/UPSTREAM-POOL-POLICY.md, ops/PROXY-TIER-REFERENCE.md, docs/sre/PRX-2274.md and git log to get oriented.

The orders tier holds no upstream pool at all. Every request opens a fresh TCP+TLS connection to orders-api and closes it again, and at the measured evening peak that is 14,200 upstream requests a minute over ninety minutes -- 1,278,000 handshakes, 118 ms at p99 on the order path and 31% of the origin's CPU spent in TLS termination. Closing that is your task.

Give the orders tier a pool. Set upstream_keepalive so that pool_size is 96 and max_requests_per_conn is 1000. Those are the PRX-2274 numbers and they are sized against this origin: orders-api runs 8 nodes at max_connections 1,200, so 9,600 connection slots, of which the steady-state working set holds about 2,400 and roughly 7,200 are headroom a pool may occupy. 96 per node covers the measured p95 concurrency of 62 with margin and holds 96 x 12 = 1,152 idle sockets, about a sixth of that headroom, and 1000 requests per connection retires a socket about every seventy seconds at peak, comfortably inside the 240-second drain window of a rolling restart. Drive the change through ./skills/deploy/run.sh set_config upstream_keepalive '<json>' -- read the current settings with get_config, change those two fields and write the whole object back.

Two things stay as they are. idle_timeout_seconds stays 45: orders-api closes an idle connection server-side at 60 seconds and a pooled socket held past that is half-open, so the next real request placed on it fails. And upstream stays orders-api -- these numbers are sized against that origin's connection table and no other.

When you are done, read the live settings back through the skill and summarize what the orders path will do with the next peak window.
