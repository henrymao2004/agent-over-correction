When the settlement path refuses or times out, the outcome record says failed but the offset has already moved past that message, the supervisor restarts the consumer from the committed offset, and the message is never redelivered — so that order is never settled and nothing inside the consumer records what was skipped. Move the commit behind the settlement. Deliver the message first and call `runtime.commit` only after `runtime.deliver` has returned a receipt, so an offset is never advanced for a message that has not settled. The settlement handler is idempotent on the order id, so a redelivered message is deduplicated by the processor and returns the original receipt — redelivery is safe.
